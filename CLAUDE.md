# deckwright

Сервис: читает произвольный `.pptx` как набор правил и собирает по нему новые
слайды. Кейс VK Tech «Цифровой дизайнер презентаций», ЛЦТ 2026.

## Стек

Python 3.11 · python-pptx + lxml (OOXML) · fontTools (метрики текста) ·
Pydantic (контракты слоёв) · LibreOffice headless (pptx→pdf) · poppler (pdf→png) ·
Streamlit (UI) · OpenAI-совместимый клиент к модели с открытыми весами.

## Команды

```bash
pip install -e ".[dev]"                                  # установка
ruff check .                                             # линтер   (gate)
pytest -q                                                # тесты    (gate)
python -m deckwright.cli run --config configs/config.yaml --template T --brief B
streamlit run app/ui.py                                  # веб-интерфейс
docker compose up --build                                # всё в контейнере
```

Гейты `ruff check .` и `pytest -q` обязаны быть зелёными в конце каждой фазы.

## Архитектура в десять строк

```
template.pptx ─►[1 parse ]─► TemplateSpec  токены, layouts, паттерны, шрифты, декор
brief+content ─►[2 plan  ]─► DeckPlan      слайды: намерение, заголовок-вывод, блоки, данные
Spec+Plan+strategy ─►[3 layout]─► SlideIR  абсолютные боксы, стили из токенов, provenance
SlideIR ─►[4 render]─► .pptx ─► .pdf ─► .png ; .html
SlideIR+.pptx+.png ─►[5 audit]─► Issue[] ─► UI ─► выбранные ─►[fix]─► 3→4→5
```

Каждый слой — пакет с одним входом, одним выходом и Pydantic-контрактом в
`schemas/`. Слои не лезут во внутренности друг друга. `SlideIR` — единый
источник истины для всех форматов экспорта и для детерминированного аудита.

Ключевое решение: шаблон используется **как донор**. Композиция не рисуется
заново, а клонируется поддеревом фигур из слайда-примера с заменой текста.
Обоснование — `research/research.md` §5.

## Правила

1. Никакого хардкода под конкретный шаблон: ни имён, ни координат, ни цветов,
   ни имён layout'ов, ни числа слайдов. Всё извлекается из файла шаблона.
2. Промпты и имена моделей — только в `prompts/` и `agents/`, версионируемыми
   файлами. В `.py` их нет.
3. Растеризация слайда в картинку для `.pptx` запрещена.
4. Никакого рефакторинга «заодно», улучшений без привязки к критерию приёмки и
   абстракций «на будущее».
5. Мусорные файлы в репозитории запрещены: отладочные скрипты, `test2.py`,
   сгенерированные артефакты вне `outputs/`.
6. Секреты только в `.env` (+ `.env.example`). В `config.yaml` — ссылки `${VAR}`.
7. Ответ LLM — структурированный JSON по Pydantic-схеме с валидацией и
   ограниченным числом повторов. Регулярки по свободному тексту запрещены.
8. «Готово» не заявляется без зелёных гейтов и прохода по критериям приёмки.
